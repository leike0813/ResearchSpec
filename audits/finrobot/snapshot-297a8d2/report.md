# FinRobot `snapshot-297a8d2` 能力审计

## 范围

本审计将官方 FinRobot 仓库绑定到提交
`297a8d28d099be328c8a8eb658b4f782b93f3651`。它涵盖所有 146 个已跟踪的 Git
条目，包括 143 个普通文件、2 个可执行文件，以及未初始化的 FinNLP gitlink。
树内的 145 个文件总计 25,906,666 字节。

FinRobot 不包含 `SKILL.md`。因此，机器真实来源清点了 66 个来源绑定的
知识表面，并将它们聚合为可能的静态能力。它不将来源角色、提示词或 Python
方法描述为上游 Skills。

权威记录是 `capability-audit.json`。本报告总结审查决策，但不替代该记录
或授权生产使用。

## 主要发现

- 根目录的 `LICENSE` 和 `NOTICE` 声明为 Apache-2.0，而 `setup.py` 仍声明为
  MIT。这是元数据冲突，而非已确认的目录级双重许可证证据。
- FinNLP 是未初始化的外部 gitlink。归因于 AutoGen 的代码以及导入的申报文件
  和标记树需要独立的来源审查。
- 固定的估值引擎包含 EV/EBITDA、同行对比和简化的 DCF 计算路径。它未实现
  文档中描述的 DDM、LBO、WACC 或蒙特卡洛方法，且树中不包含所声称的 React、
  Tauri、Rust 或三十运算符实现。
- 估值、预测、敏感性和催化剂模块使用固定假设或启发式的置信度/概率值。
  这些是审计风险，而非权威的财务默认值。
- 提示词和运行时绑定到命名的模型和市场数据提供商、凭据、远程服务以及
  时间敏感的证据。多个请求目标、评级、预测或投资含义，但缺乏稳定的来源
  和新鲜度契约。

## 未来引入边界

生产考虑需要一个单独的 `ingest-finrobot` 变更，以解决所有准入、文件、
来源、许可证、提供商/资源、重叠、审核和域决策。此处不固定生产准入数量。

未来的转换器可能仅发出静态的已审核指导。ResearchSpec 不得运行或分发
FinRobot 运行时、初始化 FinNLP、安装依赖、配置凭据、访问提供商、执行交易、
管理投资组合或提供个性化投资建议。数值结果必须来自用户批准的确定性工具，
并记录输入、假设、来源和截止日期；LLM 输出仅限于证据绑定的解释。
