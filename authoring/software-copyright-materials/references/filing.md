# R11 软著材料提交指引

本文件在本地材料已经生成、完成独立复核并由申请人选择继续提交后读取。案件目录固定为 `work/software-copyright/<case-id>/`，其中的 `草稿/` 保存未确认内容，`正式资料/` 保存已验收材料，`提交记录/` 保存授权、平台观察、等待状态、签章页和交接记录。文中的材料路径均相对案件目录。

## 一、放行与授权

### 1. 本地材料放行

使用 packet 返回的包根目录运行以下命令。`<workspace-project-root>` 是包含 `work/software-copyright/` 的项目根目录，`<case-id>` 是案件目录名。

```bash
python3 -B <package>/scripts/materials.py check-ready --root <workspace-project-root> --case <case-id>
```

只有命令成功退出且输出可解析的 JSON 才能继续。JSON 应提供 `case_fingerprint`、`artifact_paths`、`source_pages` 和 `manual_pages`。`artifact_paths` 必须包含 `application`、`source_docx`、`manual_docx`、`source_pdf`、`manual_pdf`。其中文件路径按案件目录解析，页数使用实际 PDF 页数。

每次在浏览器中上传 PDF 前都必须先运行本命令；新开浏览器会话、从本地修改材料后继续或授权范围发生变化时还要重新运行。命令失败、输出缺少上述键、`case_fingerprint` 与授权记录不同、PDF 缺失或材料发生变化时停止，保留现有文件并请申请人重新验收。此检查证明被确认的材料索引和文件摘要一致，独立复核仍由申请人及其授权检查者负责。

### 2. 选择提交路径

申请人明确选择三种路径之一。

- 本地交付，只交付 `正式资料/` 和说明，不接触平台。
- 手工指引，由申请人操作平台，Agent 提供字段、附件和回读清单。
- 宿主浏览器协助，Agent 在独立授权范围内操作当前浏览器。

提交路径的选择不构成浏览器授权。每次浏览器协助都要有新的明确范围和当前会话确认，包括平台域名、业务类型、申请人身份、`<case-id>`、`case_fingerprint`、软件全称与版本、`正式资料/申请表信息.txt` 中准备填写的字段、`source_pdf` 与 `manual_pdf` 的相对路径和页数，以及允许执行的动作。额外证明附件由申请人在当前消息中单独给出路径并授权，不并入本地材料索引。

默认只允许读取、填写已授权字段、上传授权附件和保存草稿。下载待签署签章页、上传已签章页和任何会结束当前申请流程的动作，分别需要再次确认。授权结束、页面身份不符或浏览器会话变化时，先停下并取得新的当前授权。

## 二、字段与附件

字段值以 `artifact_paths.application` 指向的 `正式资料/申请表信息.txt` 为准。填写前按文件顺序把全部字段逐项展示给申请人，包括软件全称、软件简称、版本号、软件分类、权利取得方式、权利范围、开发完成日期、开发方式、软件说明、发表状态、首次发表日期、著作权人、开发的硬件环境、运行的硬件环境、开发该软件的操作系统、软件开发环境或开发工具、该软件的运行平台或操作系统、软件运行支撑环境或支持软件、编程语言、源程序量、开发目的、面向领域或行业、软件的主要功能、软件的技术特点和页数，确认实际填写值。页面出现清单外字段或需要改变已确认值时，停止并请申请人决定。

平台带出的只读主体信息要与申请人和申请表核对。账号主体、证件类型、名称或地区不一致时，不改写本地材料去迎合页面，也不新建同名主体，先记录页面实际值并交由申请人处理。页面自动计算的页数应在上传后与 `source_pages`、`manual_pages` 比较。

程序鉴别材料只使用 `artifact_paths.source_pdf`，操作手册只使用 `artifact_paths.manual_pdf`。上传前核对相对路径和页数，选择文件后继续观察文件名、上传进度和完成状态。文件选择框选中文件不等于上传完成。

身份证明、商标证明或其他补充证明只有在申请人单独提供绝对路径并批准本次上传时才使用。不要把未列入授权的文件复制进 `正式资料/`，也不要用本地推断的文件替代平台要求的证明。

## 三、手工提交指引

1. 只打开申请人在当前授权中写明并确认为官方的域名。申请人完成账号登录、验证码、双重验证和身份校验。
2. 选择 R11 计算机软件著作权登记申请和经申请人确认的申请人身份。机构代理关系或身份选择不明确时暂停。
3. 按页面顺序填写已确认字段，优先使用页面现有选项。平台没有对应预设的语言或技术特点，只有申请人事先批准替代文本时才填写。
4. 上传授权范围内的代码 PDF 和操作手册 PDF。商标或其他证明仅在单独授权时上传。
5. 在确认页按申请表顺序逐项回读全部字段和附件状态，不得只抽查。重点核对软件全称、简称、版本、分类、开发完成日期、开发方式、发表状态、著作权人、证件信息、编程语言、源程序量、开发目的、主要功能和页数。著作权人和页数属于只读或平台计算项时，记录实际显示值并与申请表和 PDF 比较。
6. 需要保存草稿时，只执行授权范围内的保存动作。保存后读取平台流水号、当前状态和所在页面。尚未取得流水号时记作 `未取得`，不能把标题或本地案件号当作已核验的平台 ID。
7. 申请声明、承诺、身份核验、签署和最终提交由申请人完成。Agent 可以在申请人操作后协助核对页面结果，不代替申请人接受声明或作出提交决定。

## 四、宿主浏览器协助

浏览器协助只使用宿主提供的原生浏览器界面和可见页面状态。按一次一个动作推进，每次动作后回读页面。流程如下。

1. 核对浏览器地址栏的完整域名与当前授权一致。出现跳转、弹窗要求新域名或页面无法确认来源时停止。
2. 申请人完成登录、验证码、双重验证和任何身份核验。Agent 不读取、输入、保存或转述密码、验证码、Cookie 或会话令牌。
3. 回读当前账号主体，确认与授权申请人一致，再选择 R11 和授权身份。出现多个已登录账号、代理人身份或账户主体不明时停止。
4. 打开或新建申请，只填写授权字段。逐组完成 `申请信息`、`开发信息`、`功能与特点`，每组填写后回读。页面控件行为与预期不同、字段被清空或选项被重置时，按实际页面重新填写并回读，无法确认时停止。
5. 上传代码 PDF 和操作手册 PDF。每次只选择授权清单中的一个文件，核对文件名、页数和完成状态。页面显示选择成功但附件列表为空、进度未完成或文件被替换时，不继续确认。
6. 在确认页执行完整回读。授权值、账号主体、只读主体信息、附件名、页数和材料清单出现任何无法解释的差异时，记录原样文字并停止。
7. 保存草稿后读取平台流水号、状态和下一步。若平台没有立即生成可核验 ID，记录 `未取得` 和页面实际提示，等待申请人决定。

签章页生成后可以由 Agent 在已授权的下载动作内保存到 `提交记录/`，文件名为 `<软件名称>-<流水号>-签章页-待签署.<扩展名>`。申请人阅读、签署或盖章并生成清晰扫描件后，再给出已签章文件和路径。只有申请人确认签署完成并单独批准上传时，才可上传该文件。上传是非最终动作，完成后再回读状态，仍由申请人执行最终提交。

### 宿主差异与安全停止

不同宿主的浏览器控制、文件选择器、下载目录、窗口大小和弹窗处理可能不同。文件选择器打不开、无法选中精确路径、上传后无法看到完成状态、下载文件无法定位、页面结构变化或辅助控件遮挡时，保留当前观察并交给申请人在同一页面手工完成。不要安装扩展、运行页面脚本、修改 DOM、注入网络请求、读取 Cookie 或使用开发者工具绕过页面。

以下任一情况出现时停止当前浏览器动作。

- 登录、验证码、双重验证、身份核验或新的法律声明需要申请人处理。
- 域名、账户主体、R11 业务、申请人身份或案件材料与授权不一致。
- 需要填写授权外字段、改变已确认值或上传授权外文件。
- 文件选择、上传、页面状态、流水号或当前页面无法可靠回读。
- 浏览器会话过期、宿主工具失败、页面跳转异常或出现重复保存风险。
- 页面要求最终提交、签署、声明接受或其他只能由申请人完成的动作。

停止时把页面实际显示的状态、仍待完成的动作和负责人写入 `提交记录/版权中心操作记录.md`，然后交还申请人。不要使用另一个浏览器、桌面操作工具或新账号自行继续。

## 五、观察记录与恢复

`提交记录/版权中心操作记录.md` 采用同一案件持续追加。每条记录至少包含以下内容。

```text
## YYYY-MM-DD HH:MM <时区>
- 案件：<case-id>
- 本地放行：check-ready 通过，case_fingerprint=<值>
- 授权：手工 / 浏览器；当前会话范围与授权摘要
- 域名、业务、身份：<页面实际显示>
- 软件与版本：<申请表确认值>
- 当前页面：<页面标题或可见步骤>
- 平台流水号：<已观察值，或“未取得”>
- 平台状态：<页面原文>
- 已回读字段：<字段名=值，只记非敏感摘要>
- 已上传附件：<案件相对路径>；页数=<值>；页面状态=<值>
- 等待事项：<页面处理中、申请人签署、身份核验等>
- 下一步与负责人：<动作>；申请人 / Agent 当前授权范围内
```

只把页面已经显示的事实写成已观察状态。把预计、建议或待确认的动作放在“下一步”中。记录账号显示名时使用核对所需的摘要，不写密码、验证码、Cookie、完整证件号或无关个人信息。每次上传、保存、下载签章页和失败重试都追加一条记录，不覆盖旧记录。

恢复时按以下顺序进行。

1. 重新运行 `check-ready`，确认 `case_fingerprint` 与授权和最后一条记录一致。变化时停止并重新取得材料与浏览器授权。
2. 读取最后一条记录中的已核验平台流水号。没有已核验 ID 时交给申请人从平台确认，不凭名称猜测草稿。
3. 在用户中心找到该 ID 对应的申请，核对账号主体、软件全称和版本。完全一致时才打开原草稿继续。
4. 找不到唯一匹配、出现多个候选或标题与 ID 不一致时停止，不创建第二份申请，也不把旧签章页用于新申请。
5. 新浏览器会话或宿主变化时，先取得新的当前浏览器授权。授权范围可以沿用相同案件材料，动作仍需重新确认。
6. 页面显示上传处理中、待同步或状态未知时记录等待，刷新后再次回读。只有在页面明确显示失败、且申请人同意重试时才重新上传，随后确认是否产生重复附件。

## 六、签章与交付

平台生成的签章页只属于当前流水号和当前申请。下载或打印前核对软件名称和流水号，待签署件与已签章件分别保存在 `提交记录/`，不使用其他案件的签章页，不修改平台生成的主体、流水号或声明。

申请人完成签署后，先确认文件与当前流水号一致、内容清晰且包含全部页。需要上传时，单独取得该已签章文件的授权，核对路径后再操作。上传后回读上传结果和页面状态。页面仍显示待上传时先检查是否已有该文件及平台提示，不连续重复上传。

最终提交由申请人完成。申请人提交后可以把回执、成功页或状态截图保存到 `提交记录/`，文件名包含软件名称、流水号和状态。Agent 只记录实际可见结果并交付材料路径、平台 ID、最后状态、等待事项和下一步，不宣称尚未显示的成功状态。
