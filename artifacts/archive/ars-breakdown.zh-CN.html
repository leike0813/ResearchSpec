ARS 深度拆解

Academic Research Skills（ARS）上游仓库架构与逻辑分析 · 基于 vendor/ars 快照（v3.19.0，MODE_REGISTRY 2026-07-22 更新）· 生成于 2026-08
用途：为 ResearchSpec 对 ARS 的吸收重构提供理解与审阅基础。本文档为分析快照，不替代上游文件。

0 · 导读

ARS 是一个"源可用（source-available）的学术研究副驾驶框架"，以 Claude Code skills 为参考发行形态，覆盖从研究问题到论文定稿的完整链路。它的独特之处不在模型能力，而在一套高度自洽的流程纪律：39 个角色化 Agent、27 个模式、10 阶段管道、双层检查点、13 类跨技能交接合同，以及一套持续膨胀的"诚实原语"（反幻觉、反泄漏、引用忠实性验证）。

理解 ARS 的关键视角有三个，建议按此顺序阅读：

  1. 定位（§1）：ARS 先划清"不做什么"——五个被明确拒绝的自主研究机制，比它"做什么"更能解释它的设计；
  2. 结构（§2–§4）：四技能 × 模式 × Agent 团队 × 阶段流程的静态架构；
  3. 纪律（§5–§8）：checkpoint、合同、诚实原语、边界执行四层机制——这是 ARS 最重的部分，也是吸收时最难处理的部分。

1 · 定位与设计哲学

1.1 基本定位

维度内容
是什么源可用的学术研究副驾驶框架（copilot），非自主写作系统；参考发行形态为 Claude Code skills，有社区维护的 Codex 等平行发行
许可证CC BY-NC 4.0（非开源，明确禁止商业使用——SaaS、咨询打包、企业付费部署、API 包装转售均被禁止）
不是不是自主论文写作系统、不替代研究者、不主张作者身份、未经人类审阅的输出不可提交
核心承诺人类在环（human-in-the-loop）永远在线；失败模式可见而非隐藏；边界记录在案而非即兴决定

1.2 被明确拒绝的机制（Rejected Mechanisms）

POSITIONING.md 中这五条不是范围脚注，而是承重边界。每条的评审测试都是同一句问话："谁控制下一次研究状态转换？"

端到端自主研究管道
  • 从问题到稿件无需学者在每次状态转换时确认
  • 被拒：学者会沦为 AI 输出的审阅者而非作者
Idea-generation Agent
  • 替学者提出/排序/扩展研究假设或问题
  • 被拒：ARS 只可对学者自拟问题做措辞模式提示 + 苏格拉底追问，绝不代拟
Paper2X 自动生成
  • 自主把稿件转成 slides/海报/视频
  • 被拒：ARS 只能对已有传播物做"保真审计"，不替作者选内容、叙事或媒介
自主实验执行/编码
  • LLM 无监督跑实验或代码
  • 被拒：只可摄入学者声明的实验溯源（#260），不发起、不修改、不把工具输出当证据
物理湿实验自动化 API
  • 驱动移液器等自动化设备
  • 被拒：超出副驾驶范围，进入实验室基础设施领域

1.3 记录在案的非目标（Non-Goals）

  • 发表后生命周期：不追踪自有论文的被引语境、勘误、OA 自存档（monitoring_agent 只监测被引文献的新进展，不监测学者自己的产出）。
  • 跨论文研究项目级状态：ARS 不记忆任何跨论文状态——无历史 claims 注册表、无 reviewer 历史档案。唯一状态载体是单篇论文的 Material Passport，每次运行从学者显式喂入的材料开始。这是反泄漏哲学的刻意结果。
  • 机构/期刊格式 profile 内容：只提供 format_profile（#439）的机制（schema + 合成示例），永不携带任何真实机构/期刊的模板规则。

1.4 设计哲学四原则

  1. 辅助而非欺骗（Assistive, not deceptive）：Style Calibration 学用户文风、Writing Quality Check 抓 AI 典型痕迹、Disclosure Mode 生成合规声明——透明是标准。
  2. 人类在环，永远（Human-in-the-loop, always）：checkpoint 系统强制；"full mode"指全管道执行而非全自主；最多 2 轮修订循环，之后遗留问题转为"已确认的局限"而非静默解决。
  3. 失败可见（Failure modes made visible）：7 模式 AI 研究失败清单（v3.2）+ Reviewer Calibration Mode，让用户看见 AI 可能错在哪里。
  4. 边界记录而非即兴（Boundaries recorded, not improvised）：每次采纳外部系统能力触碰承重边界时，写一份 design-lesson 文档（如对 Co-Scientist 的 4 篇 L1–L4 分析、对 Kong 2026 自主研究的 2 篇），使边界可复审、可一致执行。

3.1 Mode Spectrum：Fidelity ↔ Originality

模式频谱的理论依据是 Lu et al. (2026, Nature 651:914–919) 图 1c：模板驱动产出质量高、方差低；模板自由产出多样性高但均值低、方差高。ARS 据此决定每个模式加载多少模板材料：Fidelity（重模板、可复现、低方差）vs Originality（轻模板、探索性、高方差高上限）。统计：27 模式中 Fidelity 16（59%）、Balanced 7（26%）、Originality 4（15%）——ARS 整体偏向可复现的模板侧。

3.2 两种调用模式（Invocation Mode）

Mode A — 编排器驱动（默认）
  • pipeline_orchestrator_agent 端到端跑全部阶段
  • 状态经 Material Passport 跟踪
  • 用户在每个阶段末被 checkpoint 拦住
Mode B — 逐阶段调用（跨会话恢复）
  • 用户一个阶段一个 agent 地调用，跨会话长线推进
  • 入口需显式信号：/ars-<mode> 命令或 [direct-mode] 前缀
  • 模糊的跨阶段输入默认要求澄清（intent clarification protocol）
  • 典型配合 ARS_PASSPORT_RESET=1 + resume_from_passport=<hash>

Mode B 是"灵活性"的主要出口，但它受 v3.9.2 阶段边界（Phase Boundary）约束：Bucket A（单阶段）agent 只能写自己阶段的目录，Bucket B（多阶段）agent 只做调用方指定阶段的工作。详见 §8。

6.5 Revision Patch 协议（#390）——修订最小爆炸半径

修订轮中 draft_writer_agent 不再重发射全文，而是走锚定 → 补丁 → 确定性应用 → finalizer：

  1. Anchorize：ars_anchorize_draft.py 给每个块打稳定标记 <!--block:BNNNN-->，生成块清单（base_draft_hash + 每块 old_hash），此步到应用之间任何人不得改写草稿；
  2. Patch 文档：writer 发射 sidecar 补丁（revision_patch.schema.json），块操作携带哈希前置条件，每操作追溯到 roadmap_item_ids；
  3. 确定性应用：ars_apply_revision_patch.py 两阶段 fail-closed——一个过期哈希拒绝整包且原稿字节不动；未触碰块按构造保持字节一致；结构性改动（标题改写/删除、章节数变化、触碰比>0.6）需显式确认，只有 §3.6 升级检查点可授权；
  4. 升级而非静默回退：结构重构需求→MANDATORY 用户检查点；确认全量重发射则打 mode: full_reemission_escalated 溯源戳。

应用报告（preserved_ratio、操作、新块 ID、结构标志）是 re-review 的必需输入。诚实边界声明：patch 模式消除"未触碰文本被静默改动"的通道，但不会让修订本身变得更好。academic-paper full 模式内部的 P6→4 配对循环不采用 patch（其 4b lint 要求完整 ## Draft Body）。

7 · 诚实原语：反幻觉与反泄漏机制族

ARS 最重的部分是一组持续演进的"诚实原语"——每项都对应一个具体的失败模式，且大部分有独立 schema、独立脚本、独立测试。这一层解释了为什么 ARS 看起来"刚"：它把幻觉治理做成了一族带验收门槛的机制。

7.1 反泄漏协议（Anti-Leakage，v3.3）

草稿包含未被会话材料支撑的参数化填充（数字、统计值、具体断言）时，标记 [MATERIAL GAP]；用户要么提供材料，要么接受缺口。贯彻"输入即边界"的哲学：Agent 只能写进来自本次运行显式材料的证据。

7.2 L3 引用忠实性（v3.7.3 + v3.8.0）

  • 三层引用发射（v3.7.3）：synthesis / draft_writer / report_compiler 在每条 <!--ref:slug--> 上附加定位器 <!--anchor:kind:value-->（quote / page / section / paragraph / none）。
  • 污染信号：preprint_post_llm_inflection（LLM 拐点后的预印本）+ semantic_scholar_unmatched + openalex_unmatched + crossref_unmatched（三索引三角测量，v3.9.0）。
  • claim 审计（v3.8，opt-in）：逐条被引 claim 对检索原文做 LLM-as-judge；8 行 finalizer 矩阵按 ref_retrieval_method 区分 paywall（LOW-WARN）/ fabricated（HIGH-WARN）/ anchorless（HIGH-WARN）/ audit_tool_failure（MED-WARN）。校准门槛：20 元组金标集上 FNR<0.15 + FPR<0.10 才可上线。
  • 终端策略（terminal_policies）：formatter 是"盖章检查"（只比对 policy_hash 与 Passport 当前策略，从不重跑策略逻辑）；finalizer 是唯一策略评估者。REFUSE 规则 1–12：规则 6–10（v3.8 五种 HIGH-WARN）、规则 11（v3.10 任意 severity=HIGH-BLOCK 令牌）、规则 12（v3.11 lookup_verified=false 仅在 citation_existence=strict 时拒绝，默认 advisory 可 /ars-mark-read 确认放行）。

7.3 引用存在性验证门（v3.11）

确定性引文验证：arXiv resolver + 四索引污染矩阵（k=0..4）+ 持久 SQLite 验证缓存（/ars-cache-invalidate 清除）+ 统一 lookup_verified 摘要（true / false / unresolvable 三态）。关键语义：解析器全挂时 unresolvable——绝不降级为 false（断网不是捏造证据），也绝不升级为 true。

7.4 时间完整性（v3.9.4）

三层机制：M1 timeline_extraction_agent 提取时间事实；M2 Phase 4→5 边界 5-pass 验证器（P1 算术 / P2 时代错置 / P3 比较词 / P4 因果 / P5 指示词）；M3 编译器+写作者的 Temporal Integrity Iron Rule；M6 第一方 Crossref + pdftotext 验证。

7.5 Degradation Registry（#511）——优雅降级索引

机器可读的"所有优雅降级机制"索引：每行记录失败类别、降级后状态、诊断标记、下游消费者、终端策略效果、权威文件锚点、钉住测试。设计原则：没有通用分数上限列——ARS 的门模型是三态结果 + advisory 后缀 + opt-in 终端策略，拒绝共享标量评分（"Explicitly rejected: score capping"）。registry 只索引不重述，语义唯一存在于各权威文件。

7.6 交叉模型验证（#523 / v3.17）

三个表面（设计冻结、最终编辑决定、DA 批判）支持 [CROSS-MODEL-HANDOFF v1] 信封 + 规范 Python 语法（cross_model_handoff.py）。信封/结果畸形 → [CROSS-MODEL-ERROR] → 结果 unavailable，绝不捏造判断；一致→机械填充不再调用 owner；分歧→以最小上下文重调 owner。

8 · 边界执行：从 prose 到强制

ARS 的流程纪律经历了从"提示词里写规矩"到"确定性强制"的演进。当前有四层强制机制：

8.1 Phase Boundary（v3.9.2）——阶段边界块

所有 agent 按阶段分类：Bucket A（单阶段，23 个：写操作严格限于本阶段）、Bucket B（多阶段：只做调用方指定阶段的工作）、Bucket D（元 agent，如 field_analyst，无需栅栏）。三层强制：agent 文件内的 Phase Boundary 提示块 + 咨询性验证器 check_pipeline_integrity.py + hook-enabled 运行时中的确定性 PreToolUse 写范围守卫。

8.2 写范围守卫（#134）——PreToolUse 钩子

  • 机器可读清单 ars_phase_scope_manifest.json 定义 23 个 Bucket A agent 的 allowed_write_globs（只能写自己的 phaseN_*/ 目录）；
  • 结构化写工具（Write/Edit/MultiEdit）按 glob 判定；Bucket A agent 的 Bash 一律拒绝（命令字符串不可判定 allowlist/denylist，全拒是唯一零 fail-open 策略）；
  • 已知有界膨胀：draft_writer_agent 是唯一双阶段静态并集（phase4+phase6），限制已记录在案（#330），待 Slice 3 逐调用授权；

10.5 吸收策略要点

  1. 策展而非转换：ARS 的版本化微协议（v3.6.6 四调用、盲审合同、patch 协议）必须过"提升 / 降级 / 丢弃"三道闸门，绝不把版本化 prose 原样搬进新系统。
  2. 诚实原语是可复用资产：7 模式清单、证据阶梯、DA 报告格式、校准门槛（FNR<0.15/FPR<0.10）这些是"知识 + 程序"，吸收后直接成为 checker 节点与知识包；它们不携带流程刚性。
  3. 跨技能去重是吸收的核心收益：citation_compliance（academic-paper）与 citation-check 模式、peer_reviewer_agent 与 academic-paper-reviewer、deep-research 的 DA 与 reviewer 的 DA、两个 socratic_mentor——上游的复制在吸收后应是同一批能力节点。
  4. 上游自锁文化值得借鉴但不必复制：sha256 内容锁与 mutation 测试对 prose 是"防漂移"，对 RS 的图/profile 是"防漂移 + 验收边界"——但 RS 的锁应锁 schema 与 profile 字节，而非 agent 提示文本。
  5. agent 文件是角色提示词，不是模块：39 个 agent 文件相互引用、版本耦合（如 agent 文件内引用 SKILL.md 的 § 节号）。吸收时必须把每个 agent 拆成"独立可加载的能力提示 + 依赖声明"，消除交叉引用。
