## Context

The previous rename established one kebab-case identity across package directory, `SKILL.md`
frontmatter `name`, manifest `capability_id`, and registry `source_path`. That change kept `cap-`
for namespace separation. Now that capability packages are split into a core tree
(`skills/capabilities/`) and a plugin tree (`skills/plugins/`), the root tree already supplies the
namespace. The `cap-` prefix only adds noise.

## Decisions

### Prefix-free core IDs, prefixed plugin IDs

Core packages become `<class>-<name>` (for example
`cap-analysis-evidence-synthesis` becomes `analysis-evidence-synthesis`). Plugin extension IDs keep
their `plugin-<vendor>-*` shape, so core and plugin capability names cannot collide with each other
even though both use the same kebab-case schema.

### Regeneration is authoritative

All package files are regenerated by the existing authoring converters after the authoring sources
change. Old package directories are deleted so parity audits scan exactly the published package set.
Graph profiles and tests are updated before regeneration.

### Active references are renamed; hash-pinned history is not rewritten

Current specs, docs, generators, tests, and maintenance anchors use the new IDs. Archived OpenSpec
changes, extraction artifacts, and the immutable revision-master audit retain their original
hash-pinned or historical references as provenance.

## Risks

- The ID rename is breaking for any external consumer that hard-coded `cap-*` IDs. The project has
  no public contract for core capability IDs and updates all internal active references in the same
  change.
- Audit anchors were baselined against the old package tree. This change refreshes those anchors
  without changing upstream/extraction identity; semantic reviews are preserved and only their ID
  references are updated.
