# Proposal

## Why

Before live-host acceptance, ResearchSpec needs reliable material exchange and recovery facts without turning ordinary research into a gated execution framework. The current ARSU profile manifest also drifts because patent maintenance writes into another generator's output, and stable installation removes the existing CLI before attempting replacement.

## What Changes

- Add optional, stateless inspection of explicit Procedure input and output materials, including inline input, without automatic script execution or execution permission.
- Let Navigate continue independent work and bridge ordinary materials with native capabilities while reporting unmet Procedure contracts honestly.
- Derive compact run recovery summaries and actionable diagnostics from existing graph authority.
- Show workspace-relative static Procedure eligibility without filtering the global catalog or granting plugin consent.
- Give ARSU conversion sole ownership of its profile output and refresh the genuinely reviewed patent maintenance binding.
- Remove pre-uninstallation from stable installation, verify the installed executable, and exercise the existing package and static projection acceptance paths.

## Capabilities

### New Capabilities

- `procedure-material-inspection`: Optional bounded material bindings and advisory input/output inspection for standalone Procedures.

### Modified Capabilities

- `procedure-routing`: Static eligibility in cards and optional material context in activation packets.
- `arsu-user-routing`: Open-world standalone composition and focused handling of missing materials.
- `cli-interface`: Optional Procedure payloads through existing instructions/check commands.
- `capability-graph-engine`: Derived recovery summaries with structured blockers.
- `arsu-converter`: Sole ownership of ARSU preset profile generation and its manifest.
- `patent-upstream-maintenance`: Patent maintenance checks shared profiles without privately emitting them.
- `mvp-release-readiness`: Stable-install replacement and pre-live deterministic acceptance.

## Impact

Changes touch Procedure inspection/eligibility, existing CLI catalogs and handlers, graph recovery projection, Navigate/native-worker renderers, maintenance and installation scripts, canonical usage guidance, generated documentation, and existing tests/dogfood scenarios. No dependency, public top-level command, persistent standalone registry, model call, or automatic service/script execution is added. Runtime schema remains workspace 2 and packet/envelope 1.
