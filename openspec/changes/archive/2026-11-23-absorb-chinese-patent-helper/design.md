# Design

## Decisions

- Pin the owner-approved local commit and preserve the reviewed source bytes in a curated maintainer snapshot. Record dispositions for the full upstream tree. Use the own-vendor extraction index and generated capability registry, and project the bundled capability through the existing Intellectual property materials domain.
- Give the capability two optional material bindings, `filing_source` and the existing `application_bundle`. The Agent requires a usable primary case source and resolves index paths within the workspace. The required `filing_verification` output is the Markdown verification record. It identifies actual sibling deliverables and evidence limits. The catalog advertises standalone mode when the capability has no profile.
- Use the reviewed Python 3.12 scripts and their existing argument and exit-code contracts. Keep the original CNIPA template and CC0 sRGB profile embedded so local rendering is available without downloads. Remove source-specific title and author fields from produced DOCX metadata. Treat the other official forms as external references.
- Compose independent filing work from approved case files. Existing patent graph controls keep their normal authority. The browser belongs to the host Agent and operates within the applicant-approved draft scope.

## Delivery and verification

The existing domain install and update operations deliver the bundled capability. Run the upstream conversion suite against the generated package and test catalog availability before and after domain selection. The maintainer audit traces extraction, published content, asset identity and partial-output behavior. A live CNIPA account is unnecessary for offline verification and never serves as a fixture.
